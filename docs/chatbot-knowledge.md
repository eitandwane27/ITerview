# Maintaining the ITerview assistant

## Knowledge sources

The assistant reads only `backend/knowledge/iterview-guide.md` and the public role summaries produced from `backend/config/roleConfig.js`. It does not crawl this repository, read environment files, query student records, or invoke tools. Credentials are used only by the server's AI client and are not placed in the prompt.

Edit the guide to update platform explanations. Each section needs a `## Heading` and a factual paragraph. Existing `Keywords:` metadata is ignored; answers are generated by DeepSeek, not keyword matching. The guide is reread for each request, so guide edits take effect without restarting the server. Role configuration changes require a backend restart. Keep the guide below 24 KB. A missing, oversized, or detected credential-containing guide disables conversational answers until corrected.

## Prompt and personality

The chatbot's system prompt lives in `backend/services/chatbotPrompt.js`. Edit `CHATBOT_PERSONALITY` to tune its overall voice and `CHATBOT_VOICE_EXAMPLES` to illustrate how that voice adapts to different conversations. `buildSystemPrompt()` combines them with the factual guide, public role catalogue, and response rules. This same prompt applies to every generated chat reply, including greetings, small talk, platform help, and track guidance.

`backend/services/chatbotKnowledgeService.js` supplies the factual guide and public role catalogue. The existing `roleRecommendationService.js` handles the AI request and response validation and imports the shared prompt; its name does not limit personality to recommendations. It re-exports `buildSystemPrompt()` and `getRoleCatalogue()` for existing callers. The initial welcome message is fixed frontend copy in `frontend/src/components/RecommendationChatbot.jsx`, rather than an AI-generated reply. Prompt changes require a backend restart (or the development server's automatic reload).

The intended voice is a quick-witted, approachable senior student: attentive to the student's actual interests, naturally conversational, and comfortable with playful banter. Harmless off-topic messages (such as asking for love advice) get a brief witty acknowledgment and a natural pivot toward interview practice, rather than a formal refusal or an automatic track-selection question. One fitting emoji is welcome. Small talk does not produce a track recommendation without relevant interests or a request for IT track guidance. Calm empathy takes priority for distress and troubleshooting. The examples illustrate tone rather than fixed replies. Product facts still come from the guide and live role catalogue, and the same safety boundaries and JSON response format apply.

## Native thinking mode

All ordinary conversations call DeepSeek directly at `https://api.deepseek.com` using `thinking: { type: "enabled" }` and `reasoning_effort: "high"`, following the native [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/). The model is selected from `DEEPSEEK_CHATBOT_MODEL`, then the existing `DEEPSEEK_MODEL`, then `deepseek-flash`. The server must have `DEEPSEEK_API_KEY` configured. These settings affect only this landing-page assistant.

The request reserves 8,192 output tokens for native thinking plus the final JSON answer. Only the final `message.content` is validated and returned; `reasoning_content` is never returned, stored, or logged. Tagalog, Taglish, language changes, greetings, and follow-ups are allowed within platform help and track guidance. Missing API configuration, provider failures, truncated answers, and invalid JSON return HTTP 503 for the frontend's retry flow. There is no automatic scripted recommendation fallback. Deterministic refusals for sensitive requests remain in place.

Every sentence in this guide should be safe to show publicly. Include features, navigation, onboarding, high-level scoring explanations, and ordinary troubleshooting. Never include credentials, private records, infrastructure details, backend code, hidden prompts, or exact assessment answer banks. Adding information here sends it to the configured AI provider. Public role summaries contain only role IDs, labels, and topic headings, not the full role configuration or its curated questions.

## Boundaries

The backend rejects common credential requests and instruction-override attempts before calling AI, filters suspicious history, and serializes remaining browser history as untrusted conversation data rather than replaying privileged message roles. Responses are validated as JSON, role IDs are checked against the registry, and common credential patterns and configured server secrets are screened from replies. Provider error bodies and generated content are not logged by this chatbot.

The chat endpoint allows 30 chat requests per IP every five minutes (including rejected requests), accepts at most 12 KB of JSON, limits messages to 600 characters and history to eight entries, and uses a 60-second AI timeout with no automatic retries. The IP limiter is in memory; deployments with multiple backend instances need a shared limiter and carefully configured proxy trust. Browser history is supplied by the user and is never proof of identity or authorization. Output screening checks credentials rather than reusing request-attack keyword rules, so safe explanations mentioning security are not replaced with a generic refusal.

Prompt wording and keyword checks cannot guarantee protection against every prompt injection, hallucination, encoding trick, or attempt to reconstruct public behavior. The access boundary is what protects private system data: the assistant receives public reference material and has no database, filesystem, or action tools. Treat the knowledge guide and prompt as potentially recoverable public information. The chatbot cannot hide frontend code, public endpoints, or public product behavior, and it does not replace authentication or authorization on other APIs.

## Validation

Run `node --test tests/roleRecommendationService.test.js tests/chatbotGuardrails.test.js tests/recommendationRoutes.test.js` from `backend`. These tests use fake AI responses and synthetic credentials; they do not call a provider or database.
